Runtime Security for Tool-Using AI Agents

Provenance taint tracking, conformal calibration, MCP execution boundaries, and where current defenses break

When a language model gains tool-calling privileges across email, file systems, payment APIs, or Model Context Protocol (MCP) servers, indirect prompt injection shifts from a text-generation nuisance into an unauthorized execution vulnerability. This guide synthesizes empirical findings and failure analyses from the AgentSentry research program.

1. Why text-level defenses fail at the tool boundary

Early prompt-injection defenses focused on input classification—scanning retrieved emails, web pages, or documents for attack phrasing such as "ignore previous instructions." While text detectors can achieve high recall on known phrasing templates, they suffer from two structural weaknesses in agentic deployments:

  • Schema and domain shift on unseen tool servers: When an agent connects to a new third-party MCP server (such as a CRM or external chat workspace), legitimate tool descriptions and payloads introduce unfamiliar vocabulary. In controlled AgentSentry tests on held-out CRM and chat servers, a TF-IDF lexical baseline detected all 34 observed exploits but falsely blocked 120 out of 120 clean episodes, collapsing clean-task completion from 99.7% to 59.3%.
  • Separation between text risk and action authority: Reading an adversarial email is harmless unless untrusted tokens influence a sensitive side-effecting argument—such as an email recipient, file-sharing target, or fund-transfer destination.

2. Typed tool manifests & precedence-ordered provenance tracking

Rather than classifying every incoming token string, runtime execution security inspects the origin of critical tool arguments immediately before execution. Each tool exposes a typed manifest declaring its risk class, permission scope, and critical sink parameters (for example, to in send_email or recipient in a payment call).

Given a proposed critical argument value, provenance attribution normalizes identifiers, numeric variants, and token boundaries (with word-trigram overlap for free text) and resolves the source across recorded context spans in strict precedence order:

user request  >  trusted system/directory span  >  untrusted external span  >  unattested

Taint propagates across intermediate reasoning and tool steps so previously untrusted values cannot be laundered through an intermediate summary or scratchpad variable.

3. Combining structural provenance with trajectory monitoring & conformal calibration

Provenance rules alone can be overly strict when legitimate workflows omit explicit prior attestation (yielding 95.7% clean-task success under policy-only blocking in AgentSentry, with 15/767 step-level false alarms). Pairing provenance with a 31-feature gradient-boosted trajectory monitor and Laplace-smoothed Markov surprisal over risk-class transitions improved clean-task preservation to 99.7% (matching the unprotected baseline) while reducing step-level false alarms to 3/767.

To calibrate alert thresholds without distributional assumptions on clean behavior, conformal calibration computes scores s₁, …, sₙ on a held-out clean calibration split and selects order statistic:

k = ceil((n + 1) × (1 − α))   at α = 0.05

Under exchangeability of clean episodes, this bounds clean-score exceedance at level α—crucially, it is a calibration of clean false-alarm behavior, not a worst-case guarantee against adaptive attackers.

5. Three failure modes every runtime security designer must address

  1. Scalar threshold override of deterministic rules: In the AgentSentry v3 extension, the hybrid's conformal threshold reached ~0.962 while certain untrusted critical flows scored ~0.9, allowing adaptive exploits to slip past blocking. Hard capability or information-flow invariants must never be diluted by a learned anomaly threshold.
  2. Heuristic string attribution limits: String matching can fail when an attacker splits, encodes, or paraphrases a payload (payload_split succeeded in 9/32 undefended v3 attempts), or when an attacker value happens to match a trusted span ("most-trusted match wins").
  3. External-benchmark transfer gap: Wiring only a cue-based regex detector into AgentDojo highlighted that synthetic sandboxes often under-elicit attacks and lexical heuristics do not transfer cleanly. Robust defenses require architectural data-flow isolation, explicit capability tokens, and task-aware attestation.
